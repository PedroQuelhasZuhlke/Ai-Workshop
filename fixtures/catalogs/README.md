# `fixtures/catalogs/` — M4 sourcing-against-fixtures catalog snapshot

`kicad_golden_snapshot.json` is a single pinned `FixtureAdapter` snapshot
(schema documented in the module docstring of
`src/pcbpick/sourcing/suppliers/fixture.py`) built to source every sourceable
line of [`fixtures/boms/kicad_bom.csv`](../boms/kicad_bom.csv) — the M4
golden BOM. `snapshot_id` is `fixture-kicad-golden-2026-01-15`; `fetched_at`
is a fixed past timestamp (`2026-01-15T00:00:00Z`), never wall-clock, per
`.github/instructions/testing.instructions.md`.

This is hand-authored data, not generated by running any pcbpick code. Where
a part in this snapshot represents the same physical component as a
pre-policy candidate already hand-verified in `fixtures/policy/cases/*.input.json`
(the `known_good_tier0_identical_mpn`, `known_good_tier1_capacitor_dropin` /
`known_bad_footprint_mismatch`, and `known_good_tier2_pin_compatible_ic`
cases), the electrical parameters and footprint were copied from that file so
the two fixture sets agree about the same part rather than silently drifting.

## Out of scope, on purpose

`kicad_bom.csv` contains no fuse, Y/X-class capacitor, optocoupler, or
isolation part, so this snapshot adds none either — inventing a safety-critical
part here would test nothing the BOM actually exercises. Safety-critical
sourcing/policy behavior is already covered by the `safety_*` cases in
`fixtures/policy/cases/`.

## Intentional near-duplicate MPNs

`RC0603FR-0710KL` (base SKU) vs. `RC0603FR-0710KLTR` (`-TR` tape-and-reel
packaging suffix) — same electrical part (Yageo 10k 0603 1%), same footprint,
deliberately similar strings that a naive `str.contains`-style match could
conflate. Real dedup logic (candidate assembly, built separately) has to
treat these as the same underlying part reachable via two MPN spellings, not
merge-by-string-prefix blindly.

## The multi-manufacturer-same-MPN case

`ABM3-16.000MHZ-D2Y-T` is loaded twice: once as `Abracon` (`active`,
18pF load cap, ±10ppm, ESR 60Ω — the real, correct part for Y1) and once as
`ECS Inc` (`obsolete`, 12pF load cap, ±30ppm, ESR 80Ω — a different, inferior
part that happens to share the exact same MPN string, e.g. from a catalog
data-entry error or a reused private-label number). `FixtureAdapter.details("ABM3-16.000MHZ-D2Y-T")`
can only return the first-loaded match (`Abracon`) per its documented
first-match-in-file-order limitation — it cannot disambiguate by
manufacturer on its own. `search()` exposes both as distinct `CatalogHit`s
(confirmed above), which is how a caller must disambiguate before trusting
`details()`. This same part also serves as the NRND/obsolete-lifecycle
coverage requirement — noted once here rather than duplicating another
obsolete/NRND-only decoy, since one clearly-documented instance is enough to
exercise the policy stage's lifecycle-warning path downstream.
